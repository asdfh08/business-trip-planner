# business-trip-planner
# Сервис планирования командировок

## Назначение
Приложение помогает сотрудникам компании планировать служебные
командировки: фиксировать маршрут поездки, сроки, контролировать расходы
и проверять их соответствие установленному бюджету.

Консольная версия приложения (ПР3) дополнена веб-интерфейсом на
Django (ПР5).

Приложение позволяет:
* просматривать список сотрудников в браузере;
* просматривать карточку сотрудника и его статус на текущую дату
  (в командировке / на месте);
* просматривать список командировок в браузере;
* просматривать карточку командировки: сотрудник, маршрут, даты,
  продолжительность, бюджет и сверку расходов с бюджетом;
* добавлять сотрудников и маршруты (консольная версия);
* создавать и отменять командировки (консольная версия);
* вносить фактические расходы и получать статистику (консольная версия);
* хранить данные между запусками приложения.

## Используемые технологии
* Python 3;
* Django 5.2 – веб-фреймворк;
* HTML – разметка веб-страниц;
* CSS и Bootstrap 5.3 – оформление страниц;
* pytest – автоматизированные тесты;
* flake8 – проверка качества кода.

## Целевая аудитория
Сотрудники организаций, которые оформляют служебные командировки, а
также руководители и сотрудники HR/бухгалтерии, контролирующие расходы
на поездки.

## Предметная область
Сотрудник отправляется в командировку по определённому маршруту на
заданные даты. Один сотрудник не может находиться в двух активных
командировках одновременно. Отменённая командировка не блокирует
сотрудника и позволяет запланировать новую поездку на те же даты.

## Основные сущности

### Employee – сотрудник
Атрибуты:
* `id` – уникальный идентификатор;
* `name` – ФИО сотрудника;
* `position` – должность.

Методы:
* `from_data()` – создание объекта из данных JSON (`@classmethod`);
* `__str__()` – строковое представление сотрудника.

### Route – маршрут
Атрибуты:
* `id` – уникальный идентификатор;
* `origin` – город отправления;
* `destination` – город назначения;
* `transport` – вид транспорта.

Методы:
* `from_data()` – создание объекта из данных JSON (`@classmethod`);
* `__str__()` – строковое представление маршрута.

### Trip – командировка
Атрибуты:
* `id` – уникальный идентификатор;
* `employee` – объект `Employee`;
* `route` – объект `Route`;
* `start_date`, `end_date` – даты начала и окончания;
* `budget_limit` – лимит бюджета;
* `expenses` – фактические расходы;
* `is_cancelled` – признак отмены.

Методы:
* `duration()` – продолжительность командировки в днях;
* `cancel()` – отмена командировки;
* `set_expenses()` – внесение фактических расходов;
* `get_budget_status()` – сверка расходов с бюджетом;
* `overlaps()` – проверка пересечения с периодом;
* `validate_dates()` – проверка корректности дат (`@staticmethod`);
* `__str__()` – строковое представление командировки.

## Страницы веб-интерфейса
* `/` – главная страница: описание приложения и навигация
  (view-функция `index()`);
* `/employees/` – список сотрудников: объекты `Employee` из
  `data/employees.json` (view-функция `employees()`);
* `/employees/<int:employee_id>/` – карточка сотрудника и его статус на
  текущую дату (view-функция `employee_detail()`);
* `/trips/` – список командировок: объекты `Trip` из `data/trips.json`
  (view-функция `trips()`);
* `/trips/<int:trip_id>/` – карточка командировки
  (view-функция `trip_detail()`).

Если сотрудник или командировка с указанным идентификатором не найдены,
страница возвращает код статуса 404. Для несуществующих адресов
подключена собственная страница 404 (`handler404`).

## Основные операции

### Используется в веб-интерфейсе (ПР5)
* просмотр списка сотрудников;
* просмотр карточки сотрудника;
* проверка, находится ли сотрудник в командировке на текущую дату;
* просмотр списка командировок;
* просмотр карточки командировки со связанными сотрудником и маршрутом;
* сверка расходов с бюджетом.

### Отложено до следующих работ
Эти операции реализованы в ПР3 и работают в консольной версии.
В веб-интерфейсе они появятся, когда будут добавлены формы и
POST-запросы:
* добавление сотрудника и маршрута;
* поиск сотрудника по имени;
* создание командировки;
* отмена командировки;
* внесение расходов;
* статистика по расходам.

## Хранение данных
Данные хранятся в JSON-файлах:
* `data/employees.json`;
* `data/routes.json`;
* `data/trips.json`.

При загрузке данные JSON преобразуются в объекты `Employee`, `Route`
и `Trip`, при сохранении – обратно в данные JSON. Для связи
командировки с сотрудником и маршрутом в `trips.json` хранятся их
идентификаторы `employee_id` и `route_id`.

## Назначение модулей

### `main.py`
Консольная версия приложения (сохранена с ПР3): меню, ввод данных,
пользовательские сценарии.

### `tripplanner/`
Пакет настроек Django-проекта:
* `settings.py` – настройки проекта;
* `urls.py` – маршрутизация верхнего уровня и `handler404`;
* `asgi.py`, `wsgi.py` – точки взаимодействия с сервером.

### `homepage/`
Django-приложение главной страницы:
* `views.py` – функция `page()` (общий HTML-каркас с Bootstrap и
  навигацией), view-функции `index()` и `page_not_found()`;
* `urls.py` – маршрут главной страницы.

### `employees/`
Django-приложение сотрудников:
* `views.py` – view-функции `employees()` и `employee_detail()`;
* `urls.py` – маршруты приложения;
* `models.py` – Django-модели (заполняется в следующих работах).

### `trips/`
Django-приложение командировок:
* `views.py` – view-функции `trips()` и `trip_detail()`;
* `urls.py` – маршруты приложения;
* `models.py` – Django-модели (заполняется в следующих работах).

Для маршрутов (`Route`) отдельное Django-приложение не создаётся:
маршрут – справочная сущность, на страницах он отображается как
связанный объект командировки (`trip.route`).

### `models/`
Классы предметной области и функции работы с ними (пакет ПР3):
* `employees.py` – класс `Employee` и функции работы с сотрудниками;
* `routes.py` – класс `Route` и функции работы с маршрутами;
* `trips.py` – класс `Trip` и функции работы с командировками.

### `storage.py`
Загрузка и сохранение данных: JSON → объекты Python и обратно.

### `utils.py`
Вспомогательные функции безопасного консольного ввода.

### `tests/`
Автоматизированные тесты проекта (pytest).

## Функции ПР3, используемые веб-слоем
* `load_employees()`, `load_routes()`, `load_trips()` (`storage.py`) –
  загрузка данных для страниц;
* `find_employee_by_id()` (`models/employees.py`) – карточка сотрудника;
* `find_trip_by_id()` (`models/trips.py`) – карточка командировки;
* `is_employee_traveling()` (`models/trips.py`) – статус сотрудника на
  текущую дату;
* `Trip.duration()`, `Trip.get_budget_status()` – данные карточки
  командировки.

## ПР6. Шаблоны Django

В рамках ПР6 проект переведён с формирования HTML в Python-коде (f-строки + `HttpResponse`) на шаблоны Django (`render()` + `.html`-файлы).

### Что изменилось

- **Базовый шаблон** `templates/base.html` — общий каркас: Bootstrap 5.3, навигация, футер
- **Наследование** — все страницы используют `{% extends "base.html" %}` и заполняют `{% block content %}`
- **Включение** — повторяющиеся фрагменты вынесены через `{% include %}`: навигация, карточка сотрудника, статус командировки
- **Пространства имён** — `app_name` в каждом `urls.py`, ссылки через `{% url 'app:name' %}`
- **Фильтры шаблонов** — `|length`, `|default`, `|default_if_none`, `|lower`, `|date`
- **Статические файлы** — CSS, JS, логотип подключены через `{% static %}`
- **Контекст** — данные передаются в шаблоны через словарь `context`
- **Страница 404** — на шаблоне через `handler404`
- Функция `page()` и прямое использование `HttpResponse` удалены
